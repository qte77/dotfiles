# rm-guard: prompt-free file operations in scratch folders, prompts in repos

Owner policy (2026-11-22). Lives in the user-level Claude Code config (`~/.claude`, a symlink into
`/workspaces/.claude-files`, which survives Codespace rebuilds). Seed copy for new Codespaces: the
`dotfiles` repo (`.claude/hooks/` and the rules in `.claude/settings.json`).

## Policy

| Command | Scratch roots: `/tmp`, `/home/vscode/wt`, `/home/vscode/cdpb` | Repos and the rest of `/workspaces` | Anywhere else |
| :- | :- | :- | :- |
| `rm`, `rmdir` | no prompt (relative paths resolve against the session cwd plus literal `cd` to an existing dir, not inside `( )`, `pushd` or `popd`; below the root; not the root itself, not the shared `/tmp/claude-<uid>` tree; a glob only inside a folder strictly below the root) | prompt | prompt |
| `mkdir` | no prompt (the root itself included) | no prompt (creation cannot destroy data; relative paths allowed, no `..`; a loop variable such as `/workspaces/x/$r-src` is allowed when the literal part before the first `$` is an absolute path inside a root) | prompt |
| `rm -rf` of a tool cache (`__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`, `node_modules`, `htmlcov`, `.coverage`) | no prompt | no prompt (regenerated by the next run; every target must be a cache) | prompt |
| `mv` | prompt (ask rule kept; the hook also checks both operands) | prompt | prompt |

Also always a prompt: `~`, backticks, unresolved `$VAR`, `..`, globs outside a folder strictly below a scratch root (e.g. `rm $S/*.md` in a session scratchpad passes; `/tmp/*`, `~/wt/*`, `.*` and globs in repos ask) in a target, `xargs rm`, and an unparseable command
that visibly starts with one of these commands.

Parser hardening (2026-11-22, from a security review): shell comments are stripped quote-aware (a quoted `#` stays an
operand), backslash-newline continuations are joined first, operands with control characters ask, a wrapper whose
options take values (`timeout -s KILL rm`, `env -u X rm`) asks when the command word is uncertain, any `rm`/`rmdir`
after an `ln` or `cp -s` in the same command asks, and a cache target that is a symlink asks.

## How it is built

1. **Allow rules** in `~/.claude/settings.json`: `rm`, `rm -f`, `rm -r`, `rm -rf`, `rmdir` per scratch root, and
   `Bash(mkdir *)`, and `rm -rf` rules ending in each cache name. These let the commands through without a prompt.
2. **No blanket ask rules** for `rm` or `mkdir` in the user file or the untracked project files
   (`/workspaces/.claude/settings.json`, `/workspaces/qte77/.claude/settings.json`): an ask rule in any scope beats
   every allow rule (code.claude.com/docs/en/permissions). `Bash(mv:*)` still asks.
3. **Guard hook** `rm-guard.py` (PreToolUse, matcher Bash, `"onFailure": "block"`): text rules can be fooled by
   `..`, wrappers (`timeout`, `nice`, `stdbuf`, `xargs`), extra operands or variables, so the hook resolves every
   target with `realpath` and returns "ask" when one falls outside the policy. It never returns "allow". If it
   crashes, all Bash is blocked (fail closed) until it is fixed.

Not a security boundary: `find -delete`, `git clean`, `python3 -c`, redirects and `cp` still change files without
these commands. Repos that track their own `.claude/settings.json` with `rm`/`mkdir` ask rules keep prompting.

## Changing it

- Roots: edit `ROOTS` / `CREATE_ROOTS` in `rm-guard.py` AND the allow rules together.
- After any change: `bash ~/.claude/hooks/rm-guard-test.sh` must print "all cases OK"; add a case for every new
  rule or reported false prompt.
- Backups of edited settings files sit next to them as `*.bak-<UTC stamp>`.
